# Build a Dynamic WoS Atlas Leaderboard Replica

This is the primary instruction file. Read every file in this handoff before coding.

## Goal

Build a responsive, clean-room replica of the public leaderboard at:

`https://wosatlas.com/leaderboard/`

The finished application must be dynamic. It must fetch the current leaderboard from the verified WoS Atlas API whenever the page loads or the user applies or removes a State filter.

Static JSON data is not a runtime data source. Do not ship a hardcoded leaderboard, fixture-backed production mode, generated player list, or manually copied snapshot.

## What is verified

Global Top 100:

```http
GET https://api.wosatlas.com/v1/power/leaderboard?limit=100
```

Top 100 for a State:

```http
GET https://api.wosatlas.com/v1/power/leaderboard?kid={stateId}&limit=100
```

Both requests were captured from the real website and returned `200 application/json` without a Cookie or `Authorization` header.

## Non-negotiable architecture

The frontend must call a same-origin endpoint owned by this project, for example:

```http
GET /api/leaderboard
GET /api/leaderboard?stateId=77
```

That server endpoint calls `https://api.wosatlas.com`.

Do not call WoS Atlas directly from browser code. Its observed CORS policy allows only `https://wosatlas.com`, so a replica on another domain will be blocked.

Do not fake or spoof the original `Origin` header. Verify that ordinary server-to-server access works in the target deployment. If it does not, stop and report the upstream access failure rather than silently falling back to stale data.

## Required behavior

1. Initial page load fetches the live Global Top 100.
2. The State field accepts a positive integer.
3. Typing does not fetch yet.
4. Pressing Enter commits the State ID and starts a live request.
5. The input is replaced by one blue State chip.
6. The page shows `Loading...` while the request is pending.
7. Results are replaced by the State Top 100.
8. Removing the chip immediately fetches the live Global Top 100 again.
9. The browser URL remains `/leaderboard/`; filter state is not stored in the URL.
10. An empty response shows `No ranked players.`.
11. A failed request shows a clear error state with Retry. Never display stale fixture rows as if they were live.
12. A newer request cancels or supersedes an older request so results cannot race.

## Required data mapping

| Upstream field | UI field | Rule |
| --- | --- | --- |
| `rank` | rank | Keep integer |
| `uid` | player ID | Convert to string for routes |
| `nick_name` | player name | Use `Player {uid}` when null |
| `kid` | State ID | Preserve null |
| `power` | power | Keep raw number; format only for display |
| `stove_lv` | Furnace level | Keep integer |
| `last_jump_pct` | Delta percent | Multiply non-null values by 100 for display |

Player links use `/player/{uid}`. State links use `/states/{kid}`. A null State has no link.

## Implementation choice

Respect an existing repository's conventions. For a new project, prefer a full-stack TypeScript setup that supports a same-origin server route. A Next.js App Router project is a sensible default. A client-only Vite build is insufficient unless the deployment also provides a serverless function or separate backend proxy.

Use TanStack Query or an equivalent request-state layer for cancellation, loading, error, retry, and query-key isolation. Use semantic CSS or CSS Modules for the interface.

## Definition of done

- Global and State results come from live requests, not fixtures.
- No browser request goes directly to `api.wosatlas.com`.
- The two verified upstream URL shapes are used exactly.
- Server responses are validated before they reach the UI.
- Null nickname and State values are handled correctly.
- Loading, empty, error, Retry, cancellation, and filter removal work.
- Rapid searches cannot show an older result after a newer one.
- The page closely matches `desktop-reference.jpg` and the responsive rules in `UI_BEHAVIOR.md`.
- Production build and tests pass with no console errors.
- Tests mock the external API. Production runtime does not use those mocks or any static leaderboard fixture.
- README documents the third-party dependency and the fact that freshness is limited by WoS Atlas's own backend refresh cadence.

## Dependency warning

This is an unofficial third-party API dependency, not a published compatibility contract. Keep it behind a provider interface, avoid excessive traffic, handle schema changes and `429`, and obtain permission before using it as a public production dependency. The API supplies WoS Atlas's current snapshot, not guaranteed real-time Whiteout Survival data.
